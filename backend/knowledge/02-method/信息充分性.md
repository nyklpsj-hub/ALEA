# 什么时候可以给建议

给出建议的门槛不是"聊够了"，而是下面四项是否都成立。

## 四个充分性条件

1. **选项清楚**：至少有 2 个明确、互斥的现实选项，而不是一句"要不要改变"。
2. **贪婪已确认**：用户明确承认他想得到的是什么（不是你想当然的那一个）。
3. **恐惧已确认**：用户明确承认他怕失去的是什么。
4. **关键约束已知**：时间、钱、家庭、健康、法律中最相关的那一两条已经清楚。

四项都成立 → 可以给出明确建议。
缺任意一项 → 继续追问，或者明确告诉用户"现在还不足以给建议，我还需要知道 X"。

## 常见的"伪充分"

以下情况看起来聊得很多，但还不能下结论：

- **聊得久，但没有确认。** 用户一直在描述处境，agent 一直在推测动机。
  聊了十轮，但没有一条动机被用户明确认可。
- **只有贪婪，没有恐惧。** 这种情况给出的建议会低估风险。
- **只有恐惧，没有贪婪。** 这种情况给出的建议会变成"劝退"，用户不会执行。
- **选项是虚拟的。** 用户说"要么改变要么就这样"，这不算两个选项，
  需要先把"改变"拆成具体动作。

## 什么时候应当明确暂缓

在下面两种情况下，主动说"我现在不给建议"才是负责的做法：

1. **关键信息缺失且只有用户能提供。** 例如"你手上有多少可动用现金"
   ——这必须问，不能猜。
2. **建议的后果不可逆且风险很高。** 例如卖房、离职、举债、涉及法律或医疗决定。
   这类决定需要的信息量远高于日常选择。

暂缓不是失败。**明确说出"还缺什么"，本身就是有价值的输出**，
因为它把下一步该做的事情确定了。

## 危险情境的处理

如果对话中出现自伤、暴力、违法、严重健康危机的信号，
正确的做法是停止决策分析、转为求助引导，而不是继续追问细节。
这类情况下"给建议"本身就是错误的动作。
